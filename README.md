# Statusphere for Swift

A SwiftUI version of [Statusphere](https://github.com/bluesky-social/statusphere-example-app), the AT Protocol example app where you set a status emoji and see everyone else's. It is the Swift counterpart of exercise 7 in the [atproto workshop](https://github.com/nnabeyang/atproto-workshop-ja).

## Branches

| Branch | Contents |
| :--- | :--- |
| `main` | The starting point: log in with atproto OAuth and sign out. Like [nextjs-oauth-tutorial](https://github.com/bluesky-social/nextjs-oauth-tutorial) for the Node.js version. |
| `complete` | The finished app: set a status and see Top Statuses and Recent statuses from the whole network. Like [statusphere-example-app](https://github.com/bluesky-social/statusphere-example-app). |

The difference between the two branches is what you build in the exercise.

## Requirements

- Xcode 27 (Swift 6.4)
- An iOS 27 simulator

## Getting started

```sh
git clone https://github.com/nnabeyang/statusphere-swift.git
cd statusphere-swift
open Statusphere.xcodeproj
```

Choose an iOS simulator and run the `Statusphere` scheme. You do not need an Apple ID to run the app in the simulator.

## Configuration

Settings live in `Config/Base.xcconfig`. To change them for yourself, copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig`, which git ignores, and override them there:

- `DEVELOPMENT_TEAM` and `CODE_SIGN_STYLE = Automatic` to run on your own device.
- `BUNDLE_ID_PREFIX` if the default bundle ID is already taken by another team.
- `STATUSPHERE_OAUTH_HOST` to log in as a different OAuth client.

Set these in `Local.xcconfig` rather than in Xcode's Signing & Capabilities editor; values written to the project file override the xcconfig files.

## How logging in works

The app is an atproto OAuth public client. Its client ID is the URL of its client metadata:

```
https://soyokaze.nnabeyang.com/statusphere/client-metadata.json
```

- The host comes from `STATUSPHERE_OAUTH_HOST`.
- A native client's redirect URI must use the client ID's host reversed as its scheme, so it is `com.nnabeyang.soyokaze:/oauth`. The bundle ID does not matter.
- The app asks for `atproto repo:xyz.statusphere.status`, which lets it write status records and nothing else.

To use your own client metadata, serve a JSON document like the one above from an HTTPS host you control and set `STATUSPHERE_OAUTH_HOST` to that host.

## Project layout

- `Statusphere/` — the SwiftUI app.
- `StatusphereKit/` — a local Swift package with everything that talks to the network: OAuth (with [AtprotoOAuth](https://github.com/germ-network/AtprotoOAuth)), the session saved in the Keychain, and XRPC clients generated by [swift-atproto](https://github.com/nnabeyang/swift-atproto).

### Generating Lexicon code

The Lexicons to generate code for are listed in `StatusphereKit/.atproto.json`, and the generated code is in `StatusphereKit/Sources/StatusphereKit/Lexicon`. After changing `.atproto.json`, regenerate from the `StatusphereKit` directory:

```sh
swift package --disable-experimental-prebuilts plugin \
  --allow-writing-to-package-directory \
  --allow-network-connections all:443 \
  swift-atproto
```

The fetched Lexicons are cached in `StatusphereKit/.lexicons`. If the generated code looks out of date, for example after switching branches, delete `.lexicons` and run the command again.
